# 0002 - Architecture Overview and Module Boundaries

## Status

Accepted

## Context

The app should stay small, inspectable, and easy to deploy on GitHub Pages. It still needs clear boundaries so the checklist logic, app shell, content, and tests do not collapse into one file.

## Decision

Use a static frontend with these boundaries:

- `src/app/`: app shell, providers, routing-free layout, and global UI.
- `src/features/bootstrap-map/`: the interactive bootstrap map and related domain logic.
- `src/shared/`: reusable UI primitives, constants, metadata, and utilities.
- `src/generated/`: build-time metadata generated by scripts.
- `scripts/`: local build, validation, and smoke helpers.
- `docs/`: GitHub Pages output plus public project documentation and ADRs.

## Consequences

- Feature code can grow without forcing a backend.
- Build metadata is generated, not hand-edited.
- Docs and Pages output share `docs/`, so build scripts must preserve markdown documentation.

## Alternatives Considered

- Single-file static HTML. Rejected because tests, metadata, and maintainability would suffer.
- Multi-page documentation site. Rejected for v1 because the main value is an interactive checklist map.
